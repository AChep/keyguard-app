# Age-encrypted ZIP archives

`AgeZipWriter` writes a plain ZIP directly into a binary age stream using the
upstream Rust `age` crate. `finish()` is required before publication. Closing a
writer abandons unfinished output. ZIP encryption is never layered inside age.

`AgeZipReader` owns its input, spools ciphertext to a temporary file, and
verifies the complete age stream before returning any ZIP entries. It then
seeks within the encrypted file. It does not create a plaintext ZIP on disk.
Entry sources are valid only until the reader advances or closes.

An `AgeSecret` is either an `AgePassword` or an `AgeIdentity`. Passwords are
strict UTF-8 without trimming or normalization. Writers use scrypt log N = 17
(128 MiB); readers allow up to 18 (256 MiB). An X25519 `AgeIdentity` involves
no key derivation; readers reject password-encrypted files for it. Native operations
are serialized to bound simultaneous KDF memory. Requests and responses carry
at most 64 KiB of data. Cancellation is checked between chunks; an in-flight
scrypt derivation runs to completion. Archives are limited to 100,000 entries
and 1,024 UTF-8 bytes per entry name. The pending ciphertext buffer, including
central-directory output during finalization, is capped at 16 MiB. Callers can
bound encrypted input and individual uncompressed entries.

The C and JNI interfaces use the same versioned command protocol. Errors poison
a session until it is closed. Both bridges redact panics and clear their
request/response buffers. The core uses upstream age for all cryptography.

`tests/fixtures/go-age-v1.2.1.zip.age` was generated by the official Go age CLI
with password `fixture-password`; it contains only synthetic test data. Rust
tests verify reading it and rejecting excessive scrypt work. Set
`KEYGUARD_AGE_INTEROP_OUTPUT` when running the Rust tests to write an archive for
independent decryption with the reference CLI.
